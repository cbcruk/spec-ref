# spec-ref — SPEC 카피를 코드가 참조하게 만들기

이 스킬은 **판단**만 한다. 검증은 전부 CLI 가 결정적으로 처리하므로, 판단 결과는 항상 도구의 exit code 로 확인한다.

## 절대 규칙

1. **`spec.gen.ts` 를 손으로 편집하지 않는다.** 값을 바꾸려면 `SPEC.md` 를 고치고 재생성한다.
2. **종료 조건은 도구의 exit code 지 내 판단이 아니다.** "맞게 옮긴 것 같다"로 끝내지 말고 `--json` 의 `ok: true` 를 볼 것.
3. **아무것도 자동으로 고치지 않는 게 이 도구의 원칙이다.** 검사 결과를 사용자에게 보고하고, 수정은 `SPEC.md` 또는 소비 코드에서 한다.

## 명령

설치돼 있으면 `npx spec-ref-*`, 이 저장소 안에서 작업 중이면 `pnpm gen` / `pnpm check:gen` / `pnpm scan`.

| 명령                                            | 하는 일                                     |
| ----------------------------------------------- | ------------------------------------------- |
| `spec-ref-gen <spec.md> --out <gen.ts>`         | 결정적 생성 (규약형 md 전용)                |
| `spec-ref-gen <spec.md> --check <gen.ts>`       | 신선도 게이트 — 낡았으면 exit 1             |
| `spec-ref-check --json <spec.md> <gen.ts>`      | 충실성 그물 — 누락·환각·옛규약              |
| `spec-ref-scan --json <spec.md> <gen.ts> <src>` | 소비자 그물 — 재복사(no-ref)·미소비(orphan) |

## 카피 규약 — 이걸 지키면 LLM 이 루프에서 빠진다

```md
## 저장 / 미저장 시 이탈

- 저장완료: `진료실별 자동 접수 설정을 저장했어요.`
- 타이틀: `자동 접수 설정을 중단하시겠어요?`
- 저장하지 않은 변경이 있으면 확인 모달을 띄운다.
```

- **백틱 = verbatim 카피.** 백틱 없는 항목은 서술이며 검증 대상이 아니다 (위 셋째 줄).
- **콜론 앞 라벨 = 생성물 키.** heading = 절 이름.
- 한 항목에 백틱이 여럿이면 배열이 된다.
- 라벨 없는 카피(`` - `값` ``)는 절의 `copies: []` 로 실리고 경고가 뜬다 — 라벨을 붙일 것.

## 경로 A — 규약을 지킨 SPEC.md (기본)

md→ts 가 완전히 결정적이므로 **변환에 관여하지 않는다.** 명령만 부르고 결과에 손대지 않는다.

```bash
spec-ref-gen SPEC.md --out src/spec.gen.ts
```

에러(exit 1)가 나면 원인은 항상 `SPEC.md` 쪽이다 — 중복 라벨, 중복 절 이름, 백틱 없는 옛 규약 라벨(`- 타이틀: 값`). **SPEC.md 를 고치고 재생성**한다.

## 경로 B — 자유형 SPEC.md

규약을 못 쓰는 문서(외부에서 받은 기획서 등)라면 두 선택지가 있다.

**B1 (권장) — 규약으로 마이그레이션한 뒤 경로 A.** 카피에 백틱과 라벨을 붙이는 편집을 사용자에게 제안한다. 한 번 하면 이후로는 도구가 전부 처리한다.

**B2 — 내가 변환하고 그물로 검증.** 이때만 md→ts 를 직접 쓴다. **반드시 루프를 돈다:**

```bash
spec-ref-check --json SPEC.md src/spec.gen.ts
```

`ok: true` 가 나올 때까지 반복한다. 필드별 대응:

| 필드           | 뜻                                  | 조치                                                                          |
| -------------- | ----------------------------------- | ----------------------------------------------------------------------------- |
| `missing`      | SPEC 슬롯 수보다 생성물 출현이 적음 | 빠뜨린 카피를 생성물에 추가. **같은 카피가 두 절에 있으면 두 번 실어야 한다** |
| `hallucinated` | 생성물에만 있는 값                  | 오타/변형이다. SPEC 원문을 **글자 그대로** 복사. 지어내지 말 것               |
| `legacyLabels` | 백틱 없는 `타이틀:`/`내용:` 항목    | SPEC.md 에서 값을 백틱으로 감싸는 마이그레이션 (코드 아니라 md 수정)          |

그물이 검사하지 않는 것: **배치**. 카피가 올바른 절·이름 아래 있는지는 사람 리뷰의 몫이므로, 키 네이밍은 SPEC 의 라벨을 그대로 따르고 임의로 바꾸지 않는다.

## 소비 코드 연결

생성물이 준비되면 코드가 그걸 **소비**해야 의미가 있다. 문자열을 재복사하지 말고 상수를 가져다 쓴다.

```ts
import { SPEC } from './spec.gen.ts'

export const LEAVE_TITLE = SPEC['저장 / 미저장 시 이탈'].타이틀
```

헤딩·라벨은 식별자로 억지 변환하지 않는다 — 따옴표 키 + bracket 접근이 원문을 보존하면서 `tsc` 가 존재를 검사한다.

```bash
spec-ref-scan --json SPEC.md src/spec.gen.ts src
```

| 필드     | 뜻                                  | 조치                                                           |
| -------- | ----------------------------------- | -------------------------------------------------------------- |
| `noRef`  | SPEC 카피가 코드에 하드코딩됨       | 그 리터럴을 SPEC 상수 참조로 교체 (파일:줄이 같이 나온다)      |
| `orphan` | 아무 코드도 참조하지 않는 생성물 키 | 경고다. 미구현이거나 SPEC 에서 지울 카피 — **사용자에게 확인** |

`orphan` 은 기본 게이트가 아니다(`--strict` 로만 exit 1). 판정 불가한 접근(동적 인덱스, 객체 통째 전달)은 보수적으로 "소비됨"으로 세므로 **`orphan` 목록은 과소 보고일 수 있다** — 없다고 다 소비된 건 아니다. `genImporters: 0` 이면 스캔 경로가 틀린 것이니 목록을 믿지 말고 경로부터 고친다.

## 마무리 체크

작업을 끝냈다고 보고하기 전에:

```bash
spec-ref-gen SPEC.md --check src/spec.gen.ts   # 규약형이면: 생성물이 최신인가
spec-ref-check SPEC.md src/spec.gen.ts         # 충실한가
spec-ref-scan SPEC.md src/spec.gen.ts src      # 재복사가 남았는가
tsc --noEmit                                    # 죽은 참조가 없는가
```

`SPEC.md` 와 `spec.gen.ts` 는 **함께 커밋**한다.
